# v0.11 — bridge signals and quieter framing

> Historical study: the one-off comparison scripts mentioned below were removed in the v1.0.0 cleanup. Current regression tests remain under `tests/`.

## Selected presentation

D / Bridges is the default. Existing `connections=signal`, `arcs`, `constellation` and `bridges` preview URLs remain valid. Arch height and connection density are unchanged.

A and D share a new variable-width signal treatment. Each edge has three to five deterministic tapered swells, with different lengths and peak widths. A raised-cosine profile joins each swell to a fine continuous spine with zero slope at the ends. A filled screen-space ribbon replaces the single rectangular thick dash; widths stay in CSS pixels as the camera zooms. Independent per-edge opacity dips and reduced-motion behavior are retained. The goal is restrained signal tracing, not a literal reproduction of the reference artwork.

## Shared endpoint behavior

The v0.10.2 fix froze D's endpoints as well as its interior. D now uses exactly the same displaced visible-selection centroid, target projections, visibility filtering, destination spacing, relationship scopes, density limits, distance brightness and acquisition timing as A/B/C.

Only the arch construction differs. Its underlying curve is still evaluated without the flow field. If its static projected endpoints are A/B and the shared moving endpoints are A'/B', sample t receives the offset `(1-t)(A'-A) + t(B'-B)`. Thus both diamonds stay attached to the moving scene, but the line does not sample local turbulence along its length. Its shape relative to the straight endpoint chord stays constant at a fixed camera. Camera orbit still changes the projected 3D arch normally.

`tests/bridges-browser.mjs` now checks that endpoints actually move during live flow while the endpoint-relative arch profile stays unchanged. It also checks camera reprojection and the default look. This supersedes the earlier test that required every SVG coordinate to remain fixed.
